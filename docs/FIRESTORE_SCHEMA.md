# Firestore schema (Phase 2)

One shared Firestore database. All restaurant data lives under `tenants/{tenantId}`.
`tenantId` is a Firestore auto-ID (20 alphanumeric chars) generated by trusted server code at approval time. It is the document ID and never changes.
Timestamps use server time (`serverTimestamp()` on the client where allowed, `FieldValue.serverTimestamp()` on the server).

## Top-level collections
| Path | Purpose | Client read | Client write |
|---|---|---|---|
| `platformUsers/{uid}` | Platform roles (`SUPER_ADMIN`, `PLATFORM_SUPPORT`), `status` | self; platform admins | never (server bootstrap) |
| `platformSettings/{id}` | Platform configuration | platform admins | never |
| `platformAuditLogs/{id}` | Platform audit trail | platform admins | never |
| `tenantApplications/{id}` | Owner applications (`PENDING` → server approves/rejects) | owner of the application; platform admins | create only: own, `PENDING`, fixed fields |
| `publicProfiles/{tenantId}` | Denormalised public website data (`status`, name, branding, website). Server writes; removed or set non-ACTIVE on suspension | anyone, only when `status == 'ACTIVE'` | never |
| `tenants/{tenantId}` | Tenant root: `status`, `profile`, `branding`, `website`, `settings`, `subscription`, `ownerUid`, `createdAt` | active members; platform admins | members with `SETTINGS_MANAGE`, presentation fields only |

## Tenant subcollections
Every document carries `tenantId` equal to the path. Rules reject mismatches and changes.

| Subcollection | Read | Client write |
|---|---|---|
| `members/{uid}` (`role`, `status`, `permissions[]`) | self; `STAFF_MANAGE`; platform admins | **never** (server only) |
| `branches` | any active member | `SETTINGS_MANAGE` |
| `categories`, `products`, `menus` | active members; anyone if `visibility == 'PUBLIC'` and tenant ACTIVE | `MENU_MANAGE` |
| `coupons` | active members | `MENU_MANAGE` |
| `orders` | `ORDERS_READ` or `KITCHEN_READ` | **never** (server prices and writes) |
| `customers` | `CUSTOMERS_READ`/`CUSTOMERS_MANAGE` | `CUSTOMERS_MANAGE`, no delete |
| `tables` | active members | `TABLES_MANAGE` |
| `reservations` | `RESERVATIONS_MANAGE`/`TABLES_MANAGE` | `RESERVATIONS_MANAGE`, no delete |
| `employees` | `STAFF_MANAGE` | `STAFF_MANAGE`, no delete |
| `inventory`, `suppliers`, `recipes` | `INVENTORY_READ`/`INVENTORY_MANAGE` | `INVENTORY_MANAGE`, no delete (archive instead) |
| `transactions` | `FINANCIAL_READ` | **never** (immutable ledger; corrections are new server-written entries) |
| `expenses` | `FINANCIAL_READ` | create only (append-only) |
| `reviews`, `notifications` | active members | never |
| `auditLogs` | `AUDIT_READ` | never |

## Membership document
```
tenants/{tenantId}/members/{uid} = {
  uid: string,             // equals the document ID; required for the collection-group membership lookup
  role: 'OWNER' | 'MANAGER' | 'CASHIER' | 'CHEF' | 'WAITER' | 'INVENTORY_MANAGER' | 'ACCOUNTANT' | 'STAFF',
  status: 'ACTIVE' | 'SUSPENDED' | 'REMOVED',
  permissions: string[],   // derived from config/permissions.js by the server
  createdAt, updatedAt
}
```

## Lifecycle
- Application: `PENDING` → (server) tenant created `ACTIVE` + owner membership, or application `REJECTED`.
- Tenant: `PENDING | ACTIVE | SUSPENDED | REJECTED | CANCELLED`. Anything other than `ACTIVE` blocks all tenant subcollections.
- Tenant creation and membership creation must be one idempotent server operation (Phase 5).

## Indexes
`firebase/firestore.indexes.json` declares a collection-group field index on `members.uid` (used to list a user's workspaces). Composite indexes are added per feature as queries are written.

## Design decisions to review
- Public menu data uses a `visibility` field and a public read rule, so public queries must include `where('visibility','==','PUBLIC')`.
- Membership `permissions` are stored on the member document so rules can check them. Changing `ROLE_PERMISSIONS` does not update existing members; a server migration is required.
- Each rules check costs extra document reads (membership + tenant + platform user lookups). Watch read quotas on the free tier.
